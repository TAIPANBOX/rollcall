rollcall

A signed apk feed for OpenWrt 25.12 with rollcall and luci-app-rollcall: the routers of one site watch each other over the LAN and report incidents to a chat.

Current release: v1.0.0-rc1 (apk version 1.0.0_rc1-r1). This is a release candidate.

Add the feed

On the router, as root. The first line trusts the key, the second adds the feed for the router's own architecture.

wget -O /etc/apk/keys/rollcall.pem https://taipanbox.github.io/rollcall/rollcall.pem
echo "https://taipanbox.github.io/rollcall/25.12/$(cat /etc/apk/arch)/packages.adb" >> /etc/apk/repositories.d/customfeeds.list

apk update && apk add rollcall luci-app-rollcall

The key's SHA-256, to compare with sha256sum /etc/apk/keys/rollcall.pem:

1dd696c7afce0464688a5106229723f60c8cfb9bd2f6ec296ee5fec24f57ff39

The index and every package are signed with that key. Without it apk drops the feed without a word and the packages appear not to exist. Nothing above needs --allow-untrusted. After the install the service is enabled and not started; the README goes on from there with rollcall init.

Architectures

  • aarch64_cortex-a53: has run on routers
  • aarch64_generic: built and signed, not yet run on a router
  • arm_cortex-a7: built and signed, not yet run on a router
  • arm_cortex-a9: built and signed, not yet run on a router
  • mips_24kc: built and signed, not yet run on a router
  • mipsel_24kc: built and signed, not yet run on a router
  • x86_64: built and signed, not yet run on a router

The packages are the ones the release workflow built from the tag (the release page). Each was checked against the release checksums and its build provenance attestation before it was signed for this feed, so the files here differ from those originals by the signature.

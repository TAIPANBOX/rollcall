# rollcall v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build rollcall v1: a Go service for OpenWrt in which the routers of one site watch each other over the LAN and whichever of them can reach Telegram reports incidents, with the security model of the approved security architecture.

**Architecture:** One static Go binary pair (`rollcalld` daemon, `rollcall` CLI). A pure-Go core (wire crypto, roster, per-router signed history chains, membership, classification, election, delivery) is built and proven first against an in-process simulator; OpenWrt integration (hotplug hooks, procd sandbox, firewall, packaging, LuCI) comes after. v1.1 checkpoint messages are defined in the wire format now and implemented later.

**Tech Stack:** Go 1.27 standard library (`crypto/hpke`, `crypto/ed25519`, `crypto/hkdf`, `crypto/sha256`, `crypto/rand`, `encoding/json`, `net`, `syscall`) plus `golang.org/x/crypto/chacha20poly1305`. OpenWrt 24.10 (ipk) and 25.12 (apk). LuCI JavaScript views. GitHub Actions.

**Spec:** `2026-10-22-router-group-design.md` and `2026-10-22-rollcall-security.md` (both approved 2026-10-22; the security document wins where they differ). Both move into the repo as `docs/superpowers/specs/2026-10-22-rollcall-design.md` and `docs/superpowers/specs/2026-10-22-rollcall-security.md` in Task 1.

## Global Constraints

- Module `github.com/TAIPANBOX/rollcall`; public repo, English, licence MIT; no attribution of decisions to a person in any repo file (`@decided YYYY-MM-DD` paraphrase only).
- Dependencies: Go standard library and `golang.org/x/crypto` only; any other module fails the build (Task 2 gate).
- Build: `CGO_ENABLED=0`, `-trimpath`, `-ldflags "-s -w -X main.version=<tag>"`.
- The daemon packages never import `os/exec`; TLS verification is never disabled.
- Sizes: UDP packet at most 1200 bytes; TCP frame at most 65536 bytes; 8 concurrent TCP connections; 5 s TCP read deadline; roster at most 32 members; names at most 32 characters from `[a-z0-9-]`; history at most 500 entries or 30 days.
- Timing defaults: heartbeat 5 s; suspect after 3 missed, silent after 6 (30 s); internet probe every 10 s, lost after 3 failures; Telegram reachability check (`getMe`) every 60 s; sender eligibility window 60 s; delivery grace 15 s; coalescing window 10 s; at most 1 message per second per chat; flash flush at most once per 60 s; epoch rotation every 30 days with 60 s overlap; join window 10 min; takeover after 10 min of silence from the primary.
- Network: port 7432 UDP and TCP (7431 is assigned to pmd; 7432-7436 unassigned, checked 2026-10-22); discovery group `ff02::114` (IANA "any private experiment"; confirm in Task 1); listeners only on interfaces of configured peer zones.
- Crypto: packet AEAD XChaCha20-Poly1305 with random 24-byte nonce; packet key `hkdf.Key(sha256.New, epochKey, nil, "rollcall/v1 packet", 32)`; signatures Ed25519 over `"rollcall/v1/" + kind + "\x00" + bytes`; key delivery `hpke.Seal` with `hpke.MLKEM768X25519()` keys, `hpke.HKDFSHA256()`, `hpke.ChaCha20Poly1305()`; join request key `hkdf.Key(sha256.New, joinSecret, nil, "rollcall/v1 join", 32)`.
- Encoding: JSON; a signature always covers the exact transmitted bytes; bodies are verified before they are decoded; decoders use `DisallowUnknownFields` and size limits.
- Admins: exactly one primary, `MaxAdmins = 2`, exactly one recovery public key.
- Telegram: host `api.telegram.org` only; `sendMessage` without `parse_mode`, with `link_preview_options: {"is_disabled": true}`; `getUpdates` only during chat binding.
- Runtime on the router: user `rollcall`, `no_new_privs`, seccomp, ujail; hard package dependencies `procd-seccomp`, `procd-ujail`, `ca-bundle`; no ubus access at all (refinement of security section 7: interface events arrive through hotplug and the CLI; state is read from `/sys` and `/proc`).
- Lab routers: Flint 2 and the two Beryl AX (all `aarch64_cortex-a53`); Brume 2 is never used.
- Testing discipline: every new test is run red first; features in `features/*.feature` bound to tests both ways; every gate has a teeth case; T3 packages get mutation testing; coverage is reported with its delta and never goes below the committed baseline.
- Execution: routine tasks run on Haiku 5.5 workers; tasks marked T3 are implemented on the session model; every T3 diff is reviewed whole by the session model before merge.

## Review Focus

1. A router name with non-ASCII, emoji or 200 characters: it is rejected at `invite`/`init` with a clear message, never truncated silently, and never reaches a message or LuCI unfiltered. Test in Task 7.
2. The wall clock jumps by years after NTP syncs during an incident: durations come from monotonic time and the message still shows the right length, with times marked approximate. Test in Task 13.
3. Telegram answers 429 with `retry_after`, or 403 because the owner blocked the bot: incidents stay queued, nothing spins, LuCI and `rollcall status` show "bot blocked" or "rate limited". Test in Task 16.
4. `/etc/rollcall` is full or read-only: a flush fails without crashing the daemon or losing the in-RAM history, and `status` reports the storage error. Test in Task 9.
5. A peer-zone interface has no IPv6 link-local address: discovery reports "unavailable on <iface>", static peers keep working. Test in Task 19.
